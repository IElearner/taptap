# 像素版首轮可玩切片

**目标**：把现有《山河里》改成能实际游玩的中国风像素经营游戏。美术采用大头、短身、清楚动作的原创像素角色（比例参考同类俯视动作游戏的可读性，不临摹《元气骑士》角色或素材）；保留现有物流、建造、农业、食堂、养猪和守村玩法。本轮先重做实际游戏表现并验证一条可玩的经营路线，不把32项扩展蓝图当成已实现内容，也不新造饼坊、锯木坊等当前不存在的建筑。

## 现有玩法基线（以代码为准）

当前共有 **11种建筑**，道路另作基础设施：义仓、民居、麦田、牧场、磨坊、屠宰场、食堂、伐木场、采石场、驿站、乡勇营。新局预建义仓、5格道路；10名人口、3名普通搬运工；初始库存木料72、石料40、口粮28（无限模式48）。有限模式含8步教学，模拟已支持跳过标记。建筑成本和产出定义见 [Definitions.lua](../scripts/game/Definitions.lua)，物流与初始库存见 [Simulation.lua](../scripts/game/Simulation.lua)。

现有主食链是 **麦田→磨坊→食堂**：麦田90秒一轮、每轮3袋麦粒，需要工人分四次播种/照料/收割；磨坊每1袋麦粒产2袋面粉，周期6秒；食堂每1袋面粉或鲜肉产4份口粮，周期6秒，店内储量上限8、可见餐位4。现有副链是 **麦田→牧场（麦粒饲料）→牲畜→屠宰场（3份鲜肉）→食堂**。磨坊与食堂配方在当前实现中不是12麦→12粉→24饼；首轮像素版应保留这些代码数据，不按错误的口头算式改配方。食物入仓与餐厅储量、四席进食由 [Meals.lua](../scripts/game/Meals.lua) 管理；田地和猪的实际周期分别见 [FarmCycle.lua](../scripts/game/FarmCycle.lua) 与 [RanchCycle.lua](../scripts/game/RanchCycle.lua)。

施工总工作量36，按四阶段、多个周边工作点推进；搬运和施工是普通工人可调度的任务，分批材料进工地阶段库存，工点可独立开工，不需等全部材料到齐。厨师、樵夫保持稳定专业身份。相关规则见 [ConstructionSites.lua](../scripts/game/ConstructionSites.lua) 和 `Simulation.lua`。保留道路先规划、建筑蓝图可先落地待接路、下游优先直送、存档/离线生产和无限拓荒；有限守村与乡勇营也继续可用。

## 首轮实际游玩路线与配置建议

先保留当前新局库存与人口，避免用预建整条产业链掩盖真实开局。作为开发回归路线，可由玩家按顺序建：民居（增加4名居民）、两块麦田、磨坊、食堂、牧场、屠宰场、伐木场；道路免费规划但仍需工人施工。以上建筑总成本为 **木料68、石料11**，在现有新局库存内可支付；建民居后人口14，3名搬运工加上7个生产岗位后仍留4名普工供修路、分批运输和多点施工。两块田既可测试面粉供餐，也可把部分麦粒转去牧场；实测时观察竞争与堵塞，不预设产量平衡已经通过。采石场和乡勇营随后纳入有限模式守村流程；它们不得因首个像素切片而被删掉。

教学可以跳过，但跳过后的真实新档仍只有义仓和基础道路、初始人口与库存；不得暗中预建生产链。首轮验收以实际输入操作完成“放路/规划蓝图→工人搬料入工地→多人分边施工→收麦→磨粉→厨师做饭→工人补食堂→四席分批进食”闭环为准，并覆盖牧场喂养、猪生长、屠宰供肉的支线，以及存档读档后生产、运输、施工和离线时间状态连续。测试缺口记为阻塞，不以配方/建筑数量断言通过。

## 像素视角与角色约束

- 横屏、正交相机，接近屏幕横纵方向的近俯视，轻微俯角只用于建筑体积和遮挡；地面网格轴与屏幕横纵大致对齐，避免强菱形等角视角和摄影写实背景。
- 当前像素视图采用640×360基准画布并支持拖动与缩放；世界格为64×48。动作图按40×48 cell切分，村民实际可见角色高度约24–28px，保持大头短身比例。建筑按功能占地和画面层级绘制，常规建筑约144–192px宽，义仓约128px宽；门洞高度至少达到角色身高。保持nearest-neighbor采样，不用平滑滤镜补边；角色、地面、建筑、粒子和UI维持一致的像素密度与有限暖色调色板。
- 以角色脚底为锚点，明确脚影和遮挡层。中国服装以原创短褂、绑腿、围裙、头巾/斗笠、腰包、背篓等区分搬运工、厨师、樵夫、农夫和乡勇；厨师与樵夫在休息、行走和工作中保持同一身份。动作图按40×48 cell规范表达已有的idle、walk、carry、build、farm、cook、feed、butcher等动作，不先加新模拟系统。
- 建筑保持当前功能尺寸和入口/道路规则，像素轮廓与屋顶层级可读，工作动画不能被地板或前墙错误切断。手机上触控区至少44dp；拖动地图、选择蓝图、道路连续绘制和分档缩放都要在横屏真实触控回归。已有存档结构和离线规则不得因美术替换丢失。

## 首轮交付边界

这是像素版范围和验收路线，不是正式上线声明。首个可交付目标是让用户在真实手机上试玩当前11种建筑的可玩切片，收集触控、性能与设备适配反馈；这轮验收不代表商用发布、完整32建筑或手机性能已通过。之后再按真实流程和用户试玩结果扩展内容，32类仍是长期设计蓝图。当前独立设计验收记录见 [PIXEL_V1_DESIGN_REVIEW.md](PIXEL_V1_DESIGN_REVIEW.md)。
