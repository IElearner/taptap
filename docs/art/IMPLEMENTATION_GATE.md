# 从目标样片到实际游戏

状态：制作约束，尚未达到；不构成上线验收。

`/workspace/visual-target` 是原创视觉目标工程。其 MP4/HTML 是预先编排的概念动画，不能证明现有游戏已具备这些玩法、画质或手机性能。最终游戏必须另行对照，不能拿这段片子替代运行证据。

## 保持同一套美术

- 工人的身份、服装、比例、手绘纹理和货物来自目标工程的源素材；导入游戏时保持统一世界比例、脚点与手点，不能重新用粗略几何体近似后声称一致。
- 房屋使用同一组注册过的地基、木架、墙和屋顶原画，按真实施工事件增加局部构件；建筑阶段不能独立缩放或移动基座。
- 环境整幅画是构图、色彩和纹理密度的参照。实际可建地图仍需拆分独立地表、道路、植被和建筑资源；不能把背景中已有的屋子当成可操作建筑。
- 相机、普通房屋与人物的尺度关系、光向、接地阴影和遮挡要统一。主目标全景为1920×1080、成人约54像素高；游戏缩放时各对象一起等比变化。
- 原创素材清单与源文件摘要在目标工程 `assets/provenance.json`。第三方研究截图只作为参考，不进入产品素材包。

## 第一条实际玩法链

先完成仓库、工人、原木/木料、多工位建造、麦田、磨坊、饼坊和食堂的端到端切片。普通工人的搬运、修路、施工属于同一个职业的任务；专业工人的身份保持稳定。32种建筑是完整设计范围，不代表已经全部开发。

材料在仓库/运输途中/工地库存之间真实转移；建筑总材料与工作量固定，多人独立认领工位，不能重复记工或等待统一开工。建筑可先规划、后接道路；未接路的蓝图留存并显示原因。

必须看到人取物、负重、卸料、空手离开；工具实际接触目标，局部施工有持续结果。种植、伐木、进出建筑与逐席用餐也须各自提供因果过程，不能用定时贴图变化替代。

## 样片之后的检查

1. 用实际运行中的固定全景与目标样片比较地表、建筑、人物和道路，随后检查动作，不能只给放大截图。
2. 录制正常速度连续操作：规划、接路、搬运、多人施工、供粮、进入食堂、离开并恢复工作。记录的动作来自游戏状态，不来自预编排片子的时间线。
3. 逐帧检查换动作时身份/身高不跳变、足底不漂移、手与货物不分离、工具不敲空气、前后遮挡正确。
4. 用真实横屏手机检查双指缩放、菜单触控、存档、长时间运行与性能；桌面离线渲染通过不算手机通过。
5. 设计与视觉测试分别报告实际缺口。不得用局部断言数量、建筑数量或自定百分比分数，代替整体观感和可玩性的判断。

当前目标是交付可审阅的视觉样片及完整机制设计；现有游戏的整体上线评价已撤回。
